 README: Can Pollution Markets Work in Developing
    Countries? Experimental Evidence from India



1    Overview

This is the replication package for “Can Pollution Markets Work in Developing Countries? Exper-
imental Evidence from India” by Michael Greenstone, Rohini Pande, Nicholas Ryan, and Anant
Sudarshan.
    The package contains code and data files necessary to replicate the analysis presented in the
paper. The package uses Stata, R, and MATLAB. Seven main files run all of the code to generate
the tables and figures in the paper. RunReplication.sh is a shell script that calls these seven
files. The replicator should expect the code to run for 10 to 15 minutes on a laptop.
    The raw input data is stored in 00RawData, code in 01Code, intermediate and cleaned data in
02DataPipeline, and final exhibits in 03Output. The 04Wrapper folder contains a LaTeX file called
all exhibits.tex which compiles all exhibits into a single document. The 05Logs folder
contains logs generated by running RunReplication.sh. The 06Surveys folder includes the
survey instruments.
    02DataPipeline, 03Output, and 05Logs folders can all be deleted and can then be exactly repro-
duced by running RunReplication.sh. The only remaining file is dir struct.txt which
RunReplication.sh uses to recreate the appropriate file directory structure if 02DataPipeline
and 03Output are deleted prior to running the replication. Section 2 displays the directory tree,
section 3 includes the replication instructions, section 4 describes the data, section 5 includes the
hardware and software specifications, and section 6 lists the script that generates each exhibit.

3       Instructions to Replicators

The results from the paper can be generated in two ways:


      • Option 1. Use RunReplication.sh to call all scripts.

      • Option 2. Run 9 scripts.


    Option 1 is recommended for replicators who already have access to a command line and are
able to call software from it. We provide help pages that might be useful to get this set up, but it
can be tricky. Option 2 is more straightforward and will suffice to generate all results.


3.1     Option 1: Use RunReplication.sh to call all scripts

3.1.1    Software requirements

      • Stata 17 or higher with terminal utility [ “stata” should be on PATH ]. Please find more
        information about the PATH variable for Windows and for Mac. This help page provides
        guidance for locating the Stata executable for Mac. This help page provides guidance for
        locating the Stata executable for Windows.

      • R and RStudio [ “Rscript” should be on PATH]. This help page provides guidance.

      • MATLAB 2019a or higher [ “matlab” should be on PATH ]. This help page provides guid-
        ance.

      • Bash or another POSIX compliant Unix shell [ Mac/Linux users can use the default shell;
        Windows users can use the Linux subsystem ]. This help page provides guidance.


    Note: It can be tricky to get this configured, so if you are having trouble go with Option 2.
Windows users may need to install GIT to run RunReplication.sh.

3.1.2    Instructions

To run the replication from top to bottom, go to: AnonymizedETSReplication/ and execute the
shell script RunReplication.sh by running source RunReplication.sh in the shell.
   RunReplication.sh calls the following 7 scripts to replicate the project:


   1. Emissions (Stata): 01Code/emissions/00MainStata.do

   2. Emissions (R): 01Code/emissions/00MainR.R

   3. Trading (Stata): 01Code/trading/00MainStata.do

   4. Phone survey (Stata): 01Code/phone survey/00MainStata.do

   5. Model data prep (Stata): 01Code/model/cleaning/00MainStata.do

   6. Model (MATLAB): /01Code/model/matlab/main caller.m

   7. Trading (R): 01Code/trading/00MainR.R


   These are all all run by default, but if you want to exclude scripts from a specific language
set the corresponding Run LANGUAGE flag to 0 in RunReplication.sh. For example, if you
wanted to skip all R scripts, you would replace Run R=1 with Run R=0. If you want to run the
entire project from scratch set Clean build=0. Note that compilation will fail if you run the
project from scratch, but try to skip scripts written in a particular coding language.
   In order for these scripts to execute properly, it is necessary to have the following R and Stata
packages installed with the package versions matching those listed in table 1.

    • Stata: ‘ftools‘, ‘regdhfe‘, ‘xtoverid‘, ‘estout‘, ‘mvsumm‘, ‘grstyle‘, ‘listtex‘, and ‘ivreg2‘

    • R: ‘tidyverse‘, ‘haven‘, ‘readxl‘, ‘janitor‘, ‘kableExtra‘, ‘viridis‘, ‘ggrepel‘, ‘ggpattern‘,
        ‘modelsummary‘, ‘fixest‘, ‘modelr‘, ‘cowplot‘, ‘gridExtra‘, and ‘grid‘

3.2   Option 2: Run 9 scripts

RunReplication.sh allows users to run the full replication package with one click, but if you
are having difficulty configuring your software environment to run it, you can also replicate the
project by hand by doing the following:

  1. Run Stata package installer: 01Code/installers/install Stata packages.do

  2. Run R package installer: 01Code/installers/install R packages.R

  3. Run each project script:

       (a) Emissions (Stata): 01Code/emissions/00MainStata.do

       (b) Emissions (R): 01Code/emissions/00MainR.R

       (c) Trading (Stata): 01Code/trading/00MainStata.do

       (d) Phone survey (Stata): 01Code/phone survey/00MainStata.do

       (e) Model data prep (Stata): 01Code/model/cleaning/00MainStata.do

       (f) Model (MATLAB): /01Code/model/matlab/main caller.m

       (g) Trading (R): 01Code/trading/00MainR.R

   Note: Scripts must be run in order. When running each script, the working directory must be
set to AnonymizedETSReplication/.

4      Data Availability and Provenance

The data were generated through surveys, plant trading data, and plant emissions measured be-
tween 2018 and 2021, as part of a field experiment. For more information on the different data
sources and how they were obtained, see ”Appendix B: Data” and ”Appendix C: Pollution Moni-
toring” in the paper.


4.1     Data sets

Raw data are stored in 00RawData. They are included as base data sets and are not generated by
running the replication code. These data sets were generated through surveys, plant trades, and
emissions recorded from CEMS devices. They were merged and compiled to produce the data sets
listed below. Data sets are listed based on the directory within 00RawData.


4.2     baseline/

      • BaselineCovariates 318i.dta: Baseline plant covariates including boiler characteristics, abate-
        ment equipment, and pre-experiment revenue and costs. These data were collected using the
        baseline survey in December 2018.

      • Master ETS In-sample - Plants (318i).dta: Treatment assignment and indicators for whether
        the plant was incompletely treated or removed from the sample.


4.3     cems/

      • CEMS Panel Monthly (clean, PO).dta: Plants’ CEMS purchase dates and monthly PM emis-
        sions. This data set is only used as a robustness check to test the effect of CEMS installation
        on plant emissions (Table C3: Effects of CEMS Installation on Plant Emissions).




                                                   6
4.4     emissions/

      • Historical Factors Preliminary Cleaned (Raw).dta: Raw CEMS calibration data. This data
        set is used primarily to assess if CEMS readings are consistent with manual sampling (Figure
        F4: Simultaneous CEMS and sampling comparison).

      • CEMS 2018-12-31 to 2021-04-03 StackDay Balanced HistCFs Master337s 3sample2trunc.dta:
        Daily CEMS data at the stack level. This is the primary data input used to construct plant
        emissions.

      • master-data flow-data stack-level surat-sample 20-04-2022 v3.xlsx: Stack-level flow data
        from CEMS devices. This is used to compute potential maximum pollution measures for
        plants.


4.5     phone survey/

      • Phone Survey All Covariates (Plant).dta: Endline plant information such as boiler charac-
        teristics, abatement equipment, and revenue and costs. These data were collected using the
        endline survey in 2020-2021.


4.6     trading/

      • NeMLinventory Sept2019-Mar2021.csv: Daily plant permit inventories from NeML.

      • NeMLordertrade Sept2019-Mar2021.csv*: Plant bid data from NeML.
